How the user reaches the server

Conceptual flow for a configured Route 53 failover setup.

1 · DNS lookup
User → DNS resolver → Route 53
The user asks for the website address. Route 53 answers with the configured IP address for the selected region.
2 · Website connection
User → Primary server
The browser connects directly to the primary server using the returned IP address.

A Route 53 health check monitors the primary endpoint. When unhealthy, configured failover records can return the recovery IP for new DNS queries. DNS caches can delay the change.

What each step does

  1. 1. Trigger outageSimulate the primary server failing and DNS returning the recovery server address.
  2. 2. Place example orderWhile recovery is active, add sample orders to recovery. The primary does not have these orders yet.
  3. 3. Copy to primaryOnce the primary is restored, simulate copying those recovery-side orders back to it.
  4. 4. Fail backAfter the example orders are synced, simulate DNS returning users to the primary.
